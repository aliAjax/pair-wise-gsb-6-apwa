# 字体搭配 · 发布工作台

在原 Type Pairer 基础上新增的发布工作台，解决「离线改字号/授权回连覆盖同事版本、旧审批仍放行」等问题。

## 运行

```bash
npm install
npm run dev      # 本地开发
npm test         # 52 条端到端场景断言（纯引擎，Node 直跑）
npm run build    # tsc + vite 构建
```

## 需求对应实现

| 需求 | 实现 |
| --- | --- |
| 草稿和确认快照分开放 | `PairingRecord.draft` 与 `PairingRecord.snapshot` 独立存储；确认时冻结快照（字段/授权/版本/指纹/基准 rev/获胜窗口），草稿仍可继续编辑，互不影响 |
| 离线补丁回来先核对基准 | 补丁带 `baseRevision + baseFields + baseLicense`。回连时基准一致→快进；基准落后→逐字段三方合并 |
| 冲突字段保留双方值并挡住发布 | 同字段双方都改且不同时写入 `ConflictSlot{base,local,remote}`，记录置 `conflict`，确认/发布/送审/再编辑全部被挡；逐字段裁决后才解除 |
| 授权到期或换版，审批和候选失效重算 | `reconcileRecord` 统一推导：到期→审批 `expired`、候选失效；换版→`superseded`；补授权并重新审批后自动重算候选 |
| 写入失败后从完整快照恢复 | 持久化写主存储前先把**整个工作台**写入恢复区；发布注入失败时同样先落完整快照再恢复，失败发布不落库 |
| 两个窗口同时确认，先到版本生效 | 候选单赢家 CAS：先到确认生成快照并作废旧候选，后到窗口同字段版本确认被拒（`confirm-lost-race`） |
| 重试不重复生成记录 | 确认/发布均带幂等键（`IdempotencyTable`，持久化到 localStorage），重试返回首次结果并记 `confirm/publish-deduped` |
| 旧数据只有草稿时升级 | `migrateLegacy` 把旧 `type-pairs` 升级为带授权信息的记录；授权留空 → 停在「待补授权」，补齐后才进入审批链 |

## 代码结构

- `src/workbench/types.ts` — 领域类型
- `src/workbench/engine.ts` — 纯函数引擎：状态推导、三方合并、审批/候选重算、确认 CAS、幂等、发布与快照恢复、旧数据升级
- `src/workbench/Workbench.tsx` — 三栏工作台 UI（队列 / 详情 / 审计流）
- `src/workbench/workbench.css` — 工作台样式
- `test/scenarios.ts` — 8 组场景共 52 条断言

## 推荐演示路径

1. **离线冲突**：选「Editorial calm」→「B 离线改字号 +8」→ 在草稿区把字号改成另一个值（窗口 A）→ 左侧补丁队列「回连核对」→ 冲突表保留 base/离线/同事三方值，发布被挡 → 逐字段裁决。
2. **授权到期**：顶栏「快进 7 天」多次，观察审批变 `expired`、候选失效；补 30 天授权→送审→裁决通过→候选重算。
3. **换版**：顶栏「全局换版」，所有有效审批/候选批量失效。
4. **双窗口确认**：记录处于「可确认」时点「两个窗口同时确认」，A 先生效、B 被拒；再点「重试确认（同幂等键）」，审计显示幂等命中、快照不新增。
5. **写入恢复**：确认后勾选「模拟下次写入失败」或直接点「发布（注入写入失败）」，观察完整快照恢复、发布未落库，再正常重试发布。
6. **旧数据升级**：在 localStorage 写入 `type-pairs`（旧数组）后刷新，旧草稿升级为带授权记录并停在「待补授权」。
